# Выводы о формате входа

- Пример записи является JSON-объектом OpenAI-compatible с верхнеуровневыми
  полями `stream`, `model`, `stream_options` и `messages`.
- В проверенном примере четыре сообщения с ролями `system`, `user`,
  `assistant`, `user`.
- Последнее `user`-сообщение содержит task wrapper, большой недоверенный
  `<context>` с `<source>` и актуальную команду в `<user_query>`.
- Формулировка цели повторяется после закрывающего тега. Парсер должен
  дедуплицировать повтор, а не считать его второй задачей.
- Классификация всего payload смешала бы системные инструкции, историю,
  предмет документов и текущую цель.
- Реальная единица анализа в проектном контракте — `run_id`; дочерние
  сообщения, события и вложения формируют одну бизнес-задачу.
- Вложения могут быть множественными. Их текст — недоверенный контекст и не
  должен замещать намерение пользователя.
