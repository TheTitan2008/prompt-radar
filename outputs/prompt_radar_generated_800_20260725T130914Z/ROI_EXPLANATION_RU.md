# Как читать ROI в Prompt Radar

## Что такое ROI

ROI показывает, окупается ли использование агентской платформы:

```text
ROI = (ценность сэкономленного времени - стоимость платформы) / стоимость платформы
```

Если ROI больше 0, сценарий потенциально окупается. Если меньше 0, стоимость
выше рассчитанной ценности времени.

## Potential ROI

Potential ROI - это сценарная оценка. Она отвечает на вопрос: "что будет, если
результат агента действительно полезен и заменяет baseline-процесс".

Это не доказанная экономия. Для generated_800 часть baseline взята из заранее
подготовленных паспортов и модельных оценок, поэтому отчёт честно помечает
такие значения как potential.

## Proven ROI

Proven ROI появляется только когда есть два типа доказательств:

- baseline подтверждён владельцем процесса или измерен;
- качество результата проверено на достаточной выборке.

Если есть только `MODEL_ESTIMATE`, нельзя говорить, что экономия доказана.

## Что такое baseline

Baseline - это наиболее вероятный процесс без агентской платформы. Это не
обязательно "полностью вручную с нуля".

Baseline может быть:

- ручная работа;
- Excel;
- готовый скрипт;
- помощь коллеги;
- задача не была бы сделана;
- задача была бы сделана в сокращённом виде.

Поэтому `manual_minutes` в отчёте означает "время в вероятном процессе без
агента", а не всегда "чистая ручная работа".

## Как считаются токены и стоимость

Токены используются как proxy для распределения GPU-стоимости, если нет более
точного GPU-time. Чем больше запрос потребил токенов, тем большую долю
фиксированной стоимости он получает.

Стоимость включает переменные события, GPU-амортизацию, лицензии и выбранные
fixed-cost компоненты. Неактивные лицензии не размазываются по активным runs:
они остаются отдельной строкой reconciliation.

## Как считается выделенная стоимость

Prompt Radar распределяет fixed cost по runs через Decimal и largest
remainder, чтобы сумма копеек в run ledger точно сходилась с общей стоимостью.

## Как считаются FTE-месяцы

Сэкономленные минуты переводятся в FTE-месяцы:

```text
FTE-months = saved_minutes / (working_days_per_month * working_hours_per_day * 60)
```

Это удобная бизнес-интерпретация времени, но не отдельное доказательство
причинности.

## Break-even

Break-even quality показывает, какое качество результата нужно, чтобы
платформа окупилась:

```text
q_break_even = (prompt_time + active_wait + followup + cost/25) / baseline_minutes
```

25 RUB/min - это 1500 RUB/hour / 60.

Если `q_break_even > 1`, сценарий не окупается даже при идеальном результате.
На уровне кластера q считается агрегированным уравнением, а не средним
арифметическим по runs.

## Почему неизвестные задачи ухудшают conservative ROI

Если для run нет baseline, паспорта или evidence, его нельзя просто удалить.
Стоимость уже потрачена, поэтому она остаётся в platform economics. Ценность
такого run в conservative view равна нулю.

Именно поэтому в отчётах есть:

- `insufficient_evidence_runs`
- `insufficient_evidence_cost`
- `insufficient_evidence_token_cost`
- `insufficient_evidence_share`

## Почему кластер не всегда бизнес-сценарий

HDBSCAN группирует похожие тексты. Похожие тексты могут быть разными
экономическими задачами: составить договор, проверить договор, перевести
договор и извлечь реквизиты договора.

Поэтому `cluster_economics.json` показывает:

- `cluster_coherence`
- `economic_homogeneity`
- `economic_passport_status`
- `economic_passport_reason`

Если кластер смешанный, strong ROI claim делать нельзя.

## Как читать отчёты

`economics_report.md` - главный текстовый отчёт: стоимость, ROI, break-even,
статусы evidence, риски и ограничения.

`platform_economics.json` - машинно-читаемые итоги по платформе.

`run_economic_ledger.csv/jsonl` - уровень каждого run: baseline, факторы,
episode, стоимость, potential/actual, missing evidence.

`statistics_report.html` - демонстрационный dashboard: пользователи, типы
запросов, токены, время, стоимость и зоны без evidence.

Главное правило для демо: positive potential ROI - это хороший сигнал для
валидации, но не доказанная экономия до проверки baseline и качества.
